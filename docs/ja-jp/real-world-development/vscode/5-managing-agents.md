GitHub Copilot をエージェントモードで使うと、コードベースの調査、変更の提案、ファイルの編集、コマンドの実行を自律的に行います。VS Code の Copilot Chat では、作業がローカルでリアルタイムに進むため、ツールの呼び出しやファイルの編集を逐一確認できます。差分をインラインでレビューし、個々の変更を承認または拒否し、エディターを離れずに追加のプロンプトで会話を調整・拡張できます。

この演習では、次の内容を学びます。

- アクセシビリティエージェントの作業をリアルタイムで監視します。
- 提案されたファイル編集をレビューして承認します。
- セッションの途中でエージェントに指示し、高コントラストモードに加えてライトモードの切り替え機能を追加します。

## シナリオ

[演習 4][previous-lesson]で使ったアクセシビリティ用カスタムエージェントは、高コントラストモードを実装しています。作業中にデザインチームから追加の依頼がありました。既定のテーマが暗すぎると感じるユーザー向けに、ライトモードの切り替え機能も追加したいとのことです。新しい会話を最初から始めるのではなく、既存のセッションに指示して作業を拡張します。

## Copilot の進捗を監視する

Copilot Chat ビューには、エージェントが行う各手順が表示されます。調査したファイル、実行したコマンド、提案した編集を確認できます。ファイル編集は差分と **Keep** / **Undo** の操作とともにチャット内に表示されます。

1. 演習 4 で使った Copilot Chat ビューに戻ります。
2. エージェントの作業中にチャットをスクロールし、各ツールの呼び出しを確認します。ファイルの読み取りや編集、実行を求めるターミナルコマンドが表示されます。
3. エージェントがファイルの編集を提案すると、差分がインライン表示されます。
    - 変更を承認するには **Keep** を選択します。
    - 変更を元に戻してエージェントにもう一度試してもらうには **Undo** を選択します。
4. チャット上部の **Files changed** を開くと、セッション中にエージェントが変更したファイル全体を確認できます。

> [!NOTE]
> ターミナルコマンドの実行などでツールの許可を求められると、エージェントは一時停止し **Allow** を表示します。内容を確認し、許可してもよいコマンドだけを承認してください。

5. エージェントが高コントラストモードの実装を完了するまで待ちます。最後に、変更内容の概要が表示されます。

## エージェントにライトモードを追加するよう指示する

高コントラストモードができたら、同じ会話でライトモードの切り替え機能も追加します。同じチャットセッションを続けるため、エージェントは前の作業のコンテキストを保持しています。変更したコンポーネント、スタイルの方針、設定した local storage の使い方などが含まれます。

1. Copilot Chat の入力欄に次のフォローアッププロンプトを送ります。

    ```plaintext
    Nice work! Now add a light-mode toggle alongside the high-contrast toggle. Light mode should follow the same pattern — persist via local storage and be accessible from the same area of the UI. The user should be able to enable high-contrast and light mode independently.
    ```

2. エージェントは以前の変更を調べ、ライトモードの追加を提案します。
3. 高コントラストモードと同様に、新しい編集を確認します。各差分で **Keep** または **Undo** を選択します。
4. エージェントの方針が希望と異なる場合 (たとえば、切り替え UI を意図しない方法でリファクタリングしようとする場合) は、チャット入力欄の横にある **Stop** ボタンで停止し、明確な追加指示を送ります。

> [!TIP]
> 進行中のセッションに指示する方が、最初からやり直すよりも速く済みます。フォローアッププロンプトを使って、調整を依頼します (「CSS を簡素化して、セレクターの重複ではなく CSS 変数を使う」)、方針を修正します (「3 つ目のトグルを追加せず、ライトモードを既存の設定パネルに組み込む」)、または範囲を広げます (「両方のトグルにキーボードショートカットも追加する」)。

## 作業内容をレビューする

コミットする前に、エージェントが変更した内容を確認します。

1. VS Code の **Source Control** ビューを開きます。
2. 変更されたファイルの一覧全体をレビューします。Astro コンポーネント、スタイル、関連テストが更新されていることを確認します。
3. 変更したファイルをいくつか開き、差分を確認します。カスタムエージェントが示したアクセシビリティのパターン (ARIA 属性、キーボード操作、セマンティック HTML、local storage による設定の保持) が反映されていることを確認します。
4. 問題がなければ、Source Control パネルで変更をステージしてコミットします。次のレッスンで[ブランチを公開][next-lesson]します。

## まとめと次のステップ

Copilot Chat のエージェントモードを使って、進行中のセッションを監視し、方向付けました。各ファイルの編集を確認して承認または拒否し、コンテキストを保ったままフォローアッププロンプトで作業を拡張しました。

このレッスンでは、次の内容を学びました。

- エージェントの作業をリアルタイムで監視する。
- ファイル編集を個別に承認または拒否する。
- フォローアッププロンプトで進行中のセッションに指示する。

[次のレッスン][next-lesson]では、アクセシビリティの作業をプルリクエストとして公開し、このラボを通じてローカルのカスタムエージェントが行った変更をレビューします。
